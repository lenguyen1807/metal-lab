# Hardware probes

> **AI disclosure.** Every file in this directory was generated by Claude
> (Anthropic, Claude Opus 5.5) while helping with the Metal GEMM worklog. The
> GEMM kernels in `kernels/` are the repository author's; these probes are
> not. Treat them as measurement scaffolding: read the source before trusting
> a number.

These standalone Swift programs measure what the GEMM harness in `gemm/`
cannot: the FP32 arithmetic ceiling, DRAM bandwidth, how Metal forms SIMD
groups inside a 2D threadgroup, and how much the naive kernel's thread-to-output
mapping matters. Unlike the harness, they time **GPU execution only**, using
`MTLCommandBuffer.gpuStartTime` / `gpuEndTime`, and report the median over
repeated runs after warm-up.

Shaders are compiled at runtime with `makeLibrary(source:)`, so no offline
Metal toolchain is needed. Default compile options apply (fast math on).

## Build and run

```sh
cd probes
swiftc -O m5_probes.swift -o /tmp/m5_probes
swiftc -O fma_peak.swift  -o /tmp/fma_peak
swiftc -O mps_gemm.swift  -o /tmp/mps_gemm

/tmp/m5_probes layout   # SIMD-group layout of 32x32 and 16x16 threadgroups
/tmp/fma_peak           # FP32 FMA ceiling (unrolled chains)
/tmp/m5_probes bw       # DRAM read and copy bandwidth, 1 GiB buffers
/tmp/m5_probes naive    # naive GEMM, x->column vs x->row, plus MPS FP32
/tmp/mps_gemm           # MPS FP16 and FP32 at 4096^3
```

Do not run a probe while the GEMM benchmark is running; they compete for the
GPU. `m5_probes fma` is an earlier, less-unrolled FMA probe kept for
comparison: loop overhead holds it to about 3.9 TFLOP/s.

## Results recorded on 2026-09-25

Apple M5 (10-core GPU, `applegpu_g17g`), 24 GB, macOS 26.7, on AC power.

| Probe | Result |
| --- | --- |
| `threadExecutionWidth` | 32 |
| 32×32 threadgroup layout | linear index = `x + 32y`; SIMD group = row `y`; lane = `x` |
| 16×16 threadgroup layout | one SIMD group spans two rows (`y = 0, 1`) |
| FP32 FMA ceiling (`fma_peak`) | 4.0–4.06 TFLOP/s median across configs; best single run 4.12 |
| DRAM read, 1 GiB | 117.8 GB/s median (best 122.6) |
| DRAM copy, 1 GiB (2 GiB moved) | 115.6 GB/s median (best 122.7) |
| Naive, x → column, 32×32 groups | 400.4 ms, 343 GFLOP/s |
| Naive, x → column, 16×16 / 8×8 | 346 / 348 GFLOP/s |
| Naive, x → row, 32×32 groups | 666.6 ms, 206 GFLOP/s (1.67× slower) |
| Naive, x → row, 16×16 / 8×8 | 304 / 296 GFLOP/s |
| MPS FP32 4096³ | 40.9–41.1 ms, 3.35 TFLOP/s |
| MPS FP16 4096³ | 9.22 ms, 14.9 TFLOP/s |

Caveats:

- The naive probe computes the same result as the harness's `matmul_naive`,
  but it is compiled at runtime and timed on the GPU. It measured about 6%
  slower than the harness's host-timed 377 ms. Compare mappings inside this
  probe, not across tools.
- `mps_gemm` uses zero-filled private buffers. Data values can affect power
  and clock behaviour, so treat the FP16 figure as approximate.
- Apple quotes 153 GB/s for M5 memory bandwidth; these kernels reached
  about 77% of that. A better bandwidth kernel may do somewhat better.
